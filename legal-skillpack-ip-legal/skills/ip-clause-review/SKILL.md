# /ip-clause-review-cn

审查合同中的知识产权条款，依据中国法判断权属归属、许可范围、保证与赔偿是否存在风险。逐条出具审查备忘录，按风险优先级排序，必要时提供修改建议用语。

## Instructions

1. **确认用户需求。** 若用户未提供合同文本（文件路径或粘贴文本），请先询问。

2. **获取合同。** 从文件路径或粘贴文本中读取合同内容。若未提供，询问。

3. **按下方工作流程执行。** 特别注意：
   - 确定合同类型及己方在知识产权方面所处的立场（转让方/受让方/双方）。此判断针对每份合同独立做出，而非一次性设定。
   - 若合同为劳动合同、咨询协议、工作说明书或委托创作合同，优先执行权属缺口检查。
   - 逐条出具审查意见，按风险严重程度排序。
   - 检查跨条款一致性，而非仅逐条审查。
   - 注意中国法下的特殊问题：著作人身权不可转让、职务作品与委托作品的权属默认规则、职务发明创造的报酬权、专利转让的登记要求。

4. **输出审查备忘录**，按下方模板——先列工作成果头部、底线判断、权属缺口检查、按严重程度排列的条款审查、一致性标记、法律适用说明、审批路由。

5. **尊重判断立场。** 当条款可被解释为向任何一方分配知识产权时，标记需律师审查，并列出支持各方的理由。不得自行决定主观的权属分配问题。


## Purpose

阅读合同中的知识产权条款，告诉律师每条条款的作用、其与市场惯例或团队标准立场的偏差、风险是什么，以及在适当情况下建议的具体修改用语。目标是产出律师一次阅读即可行动的备忘录。

**大多数合同中风险最高的条款是知识产权归属与转让。** 事后难以弥补。劳动合同或咨询协议中权属转让条款的薄弱或缺失，会在并购尽职调查、融资和诉讼中暴露，有时是在签署数年之后。如果一份本应包含权属转让条款的文件中转让语言薄弱或缺失，应在备忘录顶部醒目标注——而非埋没在众多条目之中。

## Workflow

### Step 1: 定位

快速通读整份合同，回答：

| 问题 | 答案 |
|---|---|
| 这是什么类型的合同？ | 劳动合同 / 咨询协议或工作说明书 / 供应商主协议 / 入方许可 / 出方许可 / 合作或联合开发协议 / 和解协议 / 资产收购 / 其他 |
| 己方在知识产权方面处于什么立场？ | 转让权利或受让权利 / 转让知识产权或取得知识产权 / 许可方或被许可方 |
| 对方是谁？ | 名称，及专业程度——个人、初创企业、大型企业 |
| 是否有针对知识产权本身的对价？ | 薪酬、费用、版税、预付款、股权、无 |
| 适用法律和管辖 | 合同约定适用什么法律——是否属于需要特别关注或升级的管辖？ |

立场判断针对每份文件独立做出。同一法务审查劳动合同时在"受让"方，同日审查出方许可时在"转让"方。立场可翻转。

若立场不明确（如合作协议中双方均贡献且均获取权利，或经销商协议中有知识产权流转），询问：

> 己方在本合同知识产权方面处于什么立场？转让权利、受让权利，还是双方？若是双方，将分别审查每个方向。

### Step 2: 权属缺口检查（最高优先级）

若合同为劳动合同、咨询协议、工作说明书、委托创作合同，或任何公司应受让对方在工作成果中知识产权的情况——优先检查权属转让语言。

检查要点：

- **职务作品归属**——劳动合同中，依据《著作权法》第18条，法人作品由法人视为作者；职务作品的著作权由作者享有，但法人有权在业务范围内优先使用；主要是利用法人物质技术条件创作并由法人承担责任的职务作品，作者享有署名权，其他权利由法人享有。检查合同是否正确约定了权属，是否覆盖了全部职务作品类型。`[model knowledge — verify]`
- **委托作品归属**——委托创作合同中，依据《著作权法》第19条，委托作品著作权的归属由委托人和受托人通过合同约定；合同未作明确约定的，著作权属于受托人。检查是否有明确的著作权归属约定。`[model knowledge — verify]`
- **职务发明创造**——依据《专利法》第6条及《专利法实施细则》，执行本单位的任务或者主要是利用本单位的物质技术条件所完成的发明创造为职务发明创造，申请专利的权利属于该单位。检查是否覆盖了职务发明创造的专利申请权归属和发明人的报酬权（实施细则相关规定）。`[model knowledge — verify]`
- **转让的现在时态**——"特此转让"或"不可撤销地转让并同意转让"。仅写"同意转让"属于承诺而非实际转让，可能需要另行签署文件才能完善。中国法下著作权转让应采用书面形式（《著作权法》第27条），专利权转让需向国务院专利行政部门登记（《专利法》第10条）。`[model knowledge — verify]`
- **范围**——是否覆盖受聘期间创作的全部知识产权，还是仅限于与公司业务相关的知识产权，还是仅限于使用公司资源创作的知识产权？若工作成果范围预期较广，过窄的范围即为缺口。
- **著作人身权**——中国法下署名权、修改权、保护作品完整权不可转让（《著作权法》第10条）。若合同试图转让著作人身权，该约定无效。应改为不可主张著作人身权的承诺或不行使著作人身权影响公司使用的声明。`[model knowledge — verify]`
- **进一步保证条款**——对方同意签署后续完善权属转让所需的任何文件。
- **已有知识产权除外**——对方从转让中排除什么，该清单是具体的还是开放式的？

如上述任何一项缺失或薄弱，在备忘录顶部标注严重程度并提供具体修改建议。

```markdown
## ⚠️ 权属缺口

**第[X]条**约定了工作成果的知识产权归属，但：[具体问题——例如，
"仅写'同意转让'而非'特此转让'"，或"未约定委托作品著作权归属，
依据《著作权法》第19条默认归受托人所有"，或"未约定专利权转让
登记，依据《专利法》第10条未登记不生效"]。

**风险：** 此类缺口可能在数年后的并购尽职调查中暴露。对方（或其继受人）
可能对本公司认为已拥有的工作成果保留残余权利。

**建议修改用语：**
> "[具体替换语言]"

**升级：** 权属范围缺口需升级至 [审批人] 审查。
```

> **转让条款能否涵盖AI生成内容？** 北京互联网法院在"李某诉刘某案"（2023）中认定AI生成内容在满足一定条件时可受著作权保护，但边界尚不明确，该领域仍在发展中 `[model knowledge — verify]`。如受托方使用AI完成交付物的重要部分，该部分的著作权状态不确定——而转让条款只能转让已有的权利。
>

>

>

>
> 检查：合同是否有AI使用声明？是否有AI参与时确定发明人资格的流程？是否有关于发明过程中AI使用的披露义务？
>
> 若上述内容缺失：标记。"专利权转让条款缺少AI使用声明。如AI工具参与了发明构思，发明人资格的认定将变得复杂，错误署名可能导致专利无效。应添加AI使用声明和发明人资格确认流程。"

### Step 3: 逐条审查

对每一项知识产权相关条款，出具审查意见块。需检查的条款：

- **权属转让 / 职务作品 / 委托作品**——合同项下创作成果归谁所有
- **交付成果所有权**——有别于权属转让；通常表述为项目产出的权利
- **改进和衍生作品**——对已有知识产权的改进归谁，衍生作品归谁
- **背景知识产权与前景知识产权**——合同是否分别定义已有知识产权和新增知识产权，并将背景知识产权许可至所需范围
- **许可授予**——范围、排他性、地域、使用领域、再许可、期限、终止触发条件、费用结构
- **知识产权保证**——不侵犯第三方权利的保证、有权授权的保证、原创性保证
- **知识产权赔偿**——范围、上限、程序、除外情形（用户修改、组合、未授权使用）
- **著作人身权处理**——中国法下的特殊问题（见Step 2相关说明）
- **开源软件声明**——关于交付物中包含哪些开源软件的声明
- **商标使用**——对方商标的授予或限制；品牌指南；许可方的质量控制
- **保密 / 商业秘密**——商业秘密资料的处理、合理措施、归还或销毁、期满后义务

对每一项存在的条款，出具：

```markdown
### 第[X.X]条：[条款名称]

**条款内容概要：** [通俗语言概述，一两句话]

**市场惯例（针对本合同类型、本方立场、中国法）：**
[简要参考基准]

**风险：** 🔴 严重 | 🟠 高 | 🟡 中 | 🟢 低

**影响：** [一两句话——如不作修改，业务上会出现什么问题]

**建议修改用语（如需）：**
> "[具体替换语言]"

**判断提示：** [如不确定条款是否实现了预期的知识产权分配，
标记需律师审查并列出支持各方的理由。
不得自行决定主观的权属分配问题。]
```

**严重程度校准：**

| 级别 | 含义 |
|---|---|
| 🔴 严重 | 不修改则不应签署。本应有权属转让的文件中出现权属缺口。本应狭窄的许可却约定为无限制。本应非排他的许可却约定为排他。 |
| 🟠 高 | 强烈要求修改；若对方不同意则升级。范围模糊、缺少著作人身权处理约定、缺少进一步保证条款、赔偿范围过窄。 |
| 🟡 中 | 首轮要求修改；若为最后一项待决事项可接受。措辞不精确但影响有限、存续期短于惯例。 |
| 🟢 低 | 记录即可，不必消耗谈判资本。不影响权利分配的措辞风格偏差。 |

### Step 4: 跨条款一致性

知识产权条款作为系统可能整体失效。检查：

- **许可授予范围是否与被许可内容匹配？**（"使用"交付成果的许可窄于"使用、修改和创作衍生作品"的许可。）
- **保证是否覆盖了授予的全部权利类型？**（仅保证不侵犯专利权，而许可同时涵盖著作权和商业秘密，存在缺口。）
- **赔偿是否覆盖了保证所承诺的内容？**（有保证无赔偿，是仅有承诺而无救济。）
- **终止是否收回许可？**（还是已付清的许可在终止后存续？两者均可接受——问题在于是否符合意图。）
- **本合同与任何相关工作说明书、订单或附属函件之间的知识产权分配是否一致？** 标记冲突。
- **著作人身权条款与权属转让条款是否矛盾？**（中国法下著作人身权不可转让，若权属转让条款与著作人身权处理不一致，需标记。）

### Step 5: 法律适用说明

知识产权规则因法域而异，影响审查结论。如合同涉及以下情形，予以标记：

- **著作人身权**——中国法下署名权、修改权、保护作品完整权不可转让（《著作权法》第10条第2款）。与英美法不同，不能通过合同约定放弃。任何需处理著作人身权的合同，必须采用"不主张"或"不行使"的表述，而非"转让"或"放弃"。`[model knowledge — verify]`
- **职务作品**——中国法下的职务作品制度（《著作权法》第18条）区分一般职务作品和特殊职务作品，权属规则不同。法人作品（《著作权法》第11条）由法人视为作者。与美国work-for-hire制度不同，中国的职务作品默认作者保留著作权（一般职务作品），仅法人享有优先使用权。`[model knowledge — verify]`
- **委托作品**——《著作权法》第19条规定委托作品著作权归属由合同约定，无约定则归受托人。与美国work-for-hire不同，中国法下委托作品不存在法定归属委托人的规则，必须依赖合同约定。`[model knowledge — verify]`
- **职务发明创造**——《专利法》第6条及实施细则规定了职务发明创造的专利申请权归属和发明人报酬权。与美国不同，中国法下发明人享有法定的报酬请求权，即使合同约定权属归单位，也不能剥夺发明人的报酬权。`[model knowledge — verify]`
- **默示许可**——中国法不承认默示许可。书面授权缺失时，不能推定存在许可。与美国等普通法法域可能推定默示许可的做法不同。`[model knowledge — verify]`
- **专利权转让登记**——《专利法》第10条第3款规定专利权转让需向国务院专利行政部门登记，转让自登记之日起生效。未登记的转让不得对抗善意第三人。`[model knowledge — verify]`
- **独占许可登记**——《著作权法实施条例》第25条规定专有许可应向著作权主管部门备案。虽然备案不影响许可合同的效力，但影响对第三人的对抗力。`[model knowledge — verify]`

说明合同约定的适用法律，以及是否属于需要特别关注或升级的管辖。

## 修改用语粒度

**以最小可能粒度进行编辑。** 修改建议是谈判工具，而非重写。整条替换意味着"我们否定了贵方的起草"——这具有攻击性，迫使对方重新阅读整条，并丢弃了贵方起草中本可保留的部分。精准修改——替换一个词、插入一个短语、调整一个子句——表示"我们有具体要求"，更易于阅读、理解和接受。

默认采用最小编辑以实现预期效果：
- 替换**词**优于替换短语。("十二(12)" → "二十四(24)")
- 替换**短语**优于替换句子。("由买方支付" → "由买方支付且应付")
- 调整**子句**结构优于替换句子。(添加"(a)"和"(b)"拆分复合条件。)
- 替换**句子**优于替换整条。
- 仅当对方版本与己方立场差距过大、精准修改反而不易阅读时，才替换**整条**——此时应说明："因修改范围较大，已替换第X.X条而非逐处标注。可向贵方逐项说明差异。"

拿不准时，粒度越小越好。收到精准修改建议的客户相信你仔细阅读了；收到整条替换的客户可能怀疑你是否真的阅读了。

### Step 6: 组装备忘录

本备忘录及所依据的合同可能享有特权、保密或兼具二者。输出继承源文件的该等属性。仅在特权范围内分发；存储于特权资料存放处；对外交付前去除工作成果头部。

> **不得默示补充。** 如对备忘录所需规则的检索返回结果较少或无结果（如某类著作人身权条款在特定场景下的可执行性、默示许可的认定标准、知识产权保证存续期的惯例），报告已获取的内容后停止。不得在未询问的情况下从网络搜索或模型知识填补缺口。说明："检索返回[N]条结果，来源[工具]。覆盖范围对于[规则/法域]似乎不足。选项：(1) 扩大检索范围，(2) 尝试其他检索工具，(3) 搜索网络——结果将标记`[web search — verify]`，应在依赖前对照一手来源核验，(4) 标记为未核验并停止。请选择。"由律师决定是否接受低置信度来源。
>
> **来源标注。** 备忘录引用法律、法规、案例或著作时，标注来源：`[国家法律法规数据库]`、`[监管机构官网]`、`[元典案例]`，或其他检索工具名称；`[web search — verify]`用于网络搜索引用；`[model knowledge — verify]`用于训练数据中召回的引用；`[user provided]`用于对方草稿或内部文件中的引用。标记`verify`的引用具有较高的编造风险，应优先核验。不得去除或合并标签。引用案例时须注明案例等级（指导性案例/典型案例/普通案例），普通案例不可作为当然适用的法律规则。引用监管文件时须标注效力状态（现行有效/已修改/已废止/征求意见稿/未核验），征求意见稿和草案不得作为现行硬性义务。

## Decision posture

当条款可被解释为向任何一方分配知识产权，或起草者选择的措辞是否实现了声明的意图尚不明确时，**标记需律师审查并列出支持各方的理由**。不得自行决定主观的权属分配问题。签署后未解决的权属分配是一扇单向门——错误会在尽职调查、融资或诉讼中暴露。标记一个事后证明无问题的模糊条款是一扇双向门。
