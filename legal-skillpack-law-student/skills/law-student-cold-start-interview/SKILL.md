# /cold-start-interview

1. 检查 `$LEGAL_AGENT_PROFILE_HOME/law-student/profile.md`。如果已填充且没有 `--redo`，在覆盖前确认。如果缓存路径中存在已填充的配置但配置路径下不存在，将其复制到配置路径并告知用户迁移了什么。
2. 应用下方的访谈工作流。
3. 走完第0部分（谁在用/连接了什么）、第1部分（你在哪里）、第2部分（你怎么学——追问型vs讲解型）、第3部分（强项/短板/回避）、第4部分（材料摄入——目标10-20项）。
4. 重读已记录的答案。捕捉矛盾、漂移的细节、值得命名的空白。
5. 写入业务规范（必要时创建父目录）。如果分享的材料少于10项，添加 `数据有限` 标记。
6. 与用户确认："以下是我记录的内容——有什么错误吗？"

**`--check-integrations`：** 仅重新运行第0部分的集成可用性检查。更新 `## 可用集成`，不触及画像其余部分。在添加或移除 MCP 连接器后使用。

探测时：仅当 MCP 工具调用实际成功时才报告 ✓。已配置但未测试的连接器应标记为 ⚪，附带一行确认方法。永远不要仅基于 `.mcp.json` 声明报告 ✓。

## 目的

其它的 cold-start 了解的是组织。这个了解的是你。你怎么学习、你回避什么、你想要被追问还是被铺垫。

## Cold-start 检查

读取 `$LEGAL_AGENT_PROFILE_HOME/law-student/profile.md`：
- **不存在** → 开始访谈。
- **包含 `<!-- 设置暂停于： -->`** → 向学生问好并提供从该部分恢复。
- **包含 `[待填写]` 标记但没有暂停注释** → 模板从未完成；提供重新开始或从占位符开始处恢复。
- **已填充（无占位符，无暂停注释）** → 已配置；跳过除非 `--redo`。

模板结构位于 `skillpack/profiles/templates/law-student/profile.md`——将其作为章节骨架。将完成的业务规范写入配置路径，必要时创建父目录。如果存在旧格式配置但当前配置路径尚未生成，将其复制过来。

## 检查共享公司画像

查找 `$LEGAL_AGENT_PROFILE_HOME/company-profile.md`。

- **如果存在：** 读取它。显示一行确认。如果确认，跳过基础信息问题——直接进入插件特定的问题。
- **如果不存在：** 你是用户设置的第一个插件。询问基础信息并写入共享画像，然后继续插件特定的问题。告知用户："我已保存你的基础画像——其它法律插件会读取它并跳过这些问题。"

>
> 快速还是完整？（随时用 `/law-student:cold-start-interview --full` 升级。）

## 用户选择快速或完整后

用自己的话覆盖：

- **本插件维护什么：** 你的画像（课程、考试日期、薄弱领域、学习风格）、学习计划、按科目的知识体系大纲、记忆卡片桶和练习考试日志。
- **本设置做什么：** 帮助学生以适合实际学习方式的形式学习法律——大纲、案例摘要、课堂准备、考试预测、法考备考。了解学习风格、科目和考试安排，写入插件每次从中读取的纯文本文件。一切都可以后续更改。
- **数据来源：** 设置仅从学生的回答中构建新的学习设定。不读取个人历史、其它对话或主目录中的其它配置文件。没有学生输入或批准，任何内容都不会添加到配置中。

**为什么这很重要。** 本插件的每个命令都从本次访谈写入的配置中读取。通用配置给出通用输出。告诉插件学生实际怎么学习——追问型vs讲解型、科目、教师、回避什么——是区分"一个学习AI工具"和"一个以你需要的方式推你的工具"的关键。

### 快速入门或完整设置——分流

**快速入门路径：** 仅询问基本信息（你是谁、在学什么、法考目标如适用）。写入配置，其余内容标记 `[默认]`。结束时说："完成。你现在可以开始使用各命令了。当某个技能的输出感觉不对时，通常意味着你应该调整某个默认值——它会告诉你哪个。随时运行 `/law-student:cold-start-interview --full` 进行完整访谈。"

**完整设置路径：** 下方现有的访谈流程。

## 访谈节奏

- **假设答案存在于某处。** 当问题询问的可能已经写在某处的信息时，在让学生凭记忆输入之前，先提示链接或粘贴。"粘贴链接或文档，或给我简短版本"是对于任何超过一句话的内容的默认请求。

**为真正的回答暂停：**
- 当一个问题需要超过快速点击时，明确说："这个问题需要输入回答——我会等。"
- 对于上传："粘贴内容、分享文件路径，或者说'暂时跳过'。如果跳过，我会在业务规范中标记空白，以便你稍后补充。"然后真的等待。
- 在写入业务规范之前，列出每个被跳过或用占位符回答的问题。等待回答。
- **永远不要**写入带有默默空白的业务规范。
- **暂停和恢复。** 告知学生可以暂停。当学生暂停时，写入部分配置并加上暂停注释。再次运行时从停下的地方继续。
- **批量大小。** 一次不要超过2-3个可回答的提示。

**在设置中遇到用户陈述的法律事实时进行验证。** 当用户用特定的法条引用、法条编号、案例名称、日期等回答访谈问题时，在写入配置之前进行合理性检查。如果冲突，指出来。一个写入配置的错误事实会传播到未来每一次输出中。

## 访谈

### 开场

> 我将帮助你学习法律。不是通过给你答案——而是通过让你为答案努力。但首先我需要知道你如何学习。十到十五分钟。
>
> 在此过程中我也会要求你提供材料——以往的大纲、历年试题、评分作业、教学大纲。整个访谈中十到二十份文档是目标。越多越好。你写过的论文也算。如果你分享的少于十份，我会将业务规范标记为数据有限——技能仍然能用，但输出会更薄。

### 第0部分：谁在用，连接了什么

#### 谁在用？

> 你是法学院学生、法考备考者，还是其它使用此工具进行法律学习的人？
>
> 1. **法学院在校生** —— 大一/大二/大三/大四本科生；法学硕士；法律硕士（法学/非法学）；法学博士；在读。
> 2. **法考备考者** —— 已毕业，正在准备国家统一法律职业资格考试（法考）。
> 3. **其它** —— 因非学历教育原因使用这些工具学习法律材料（自学、转行、相关领域工作）。

如果答案是1或2（在校生或法考备考者），说一次：

> 关于在学校或法考中使用此工具的两点提醒：
>
> 1. **在将本工具用于任何评分作业之前，请检查你学校的学术诚信规范和授课教师的 AI 政策。** 大多数学校区分学习工具（可以）和考试/评分作业辅助（通常受限或禁止）。本插件为学习而建。
> 2. **不要将真实的当事人事实粘贴到本插件中。** 如果你在法律诊所、实习或暑期工作中，某个学习问题触碰到了真实事项，请停止——使用你诊所或工作的经批准的工作流程。

如果答案是3（其它），说一次：

> 你可以使用所有功能，方式与学生相同。有两件事在框架上会有所不同：
>
> 1. **我会将输出框定为学习材料，而非法律意见。** 学习法理与将法理应用于你自己的情况不同。如果你因为自己正面临真实法律问题而使用此工具，请咨询律师。
> 2. **如果看起来你已从学习转入真实事项，我会暂停。**

**真实当事人事项检查（适用于所有角色）：** 如果用户描述带有真实事实的真实事项而非学习假设，暂停并重定向。在用户确认这是学习假设或已被重定向之前，不要继续分析具体事实。按事项类型路由到对应 cluster 或专业资源：

| 事项类型 | 建议路由 |
|---|---|
| 劳动 / 入职 / 解除 / 工资 | employment-*（termination-review / hiring-review / wage-hour-qa） |
| 合同纠纷 / 商事 / 催告函 | commercial-*（contract-review）或 litigation-*（demand-draft / demand-intake） |
| 数据 / 个人信息 / 隐私 | privacy-*（use-case-triage / dsar-response） |
| AI 治理 / 算法 / 备案 | ai-governance-*（use-case-triage / vendor-ai-review） |
| 新案件 / 起诉 / 诉讼程序 | litigation-*（matter-intake / matter-briefing） |
| 通用法律咨询 / 无法分类 | 执业律师 / 法律援助（拨打12348）/ 学校法律诊所 |

#### 连接了什么？

> 本插件可以与文档存储（飞书云文档、阿里云盘、百度网盘、本地文件）配合使用。让我检查你配置了哪些连接器。

**检查实际连接了什么，而非配置了什么。** 对于每个连接器：实际测试成功→报告 ✓；无法测试→⚪ 并附确认方法；未找到→✗ 附连接说明。永远不要仅基于配置报告 ✓。

- `yuandian-case`（元典案例检索 MCP）— https://open.chineselaw.com/mcp/case/stream

API 密钥获取：https://apiplatform.legalmind.cn/api-square

- 如未连接：✗ "元典 MCP 未连接——所有引用将标记 `[模型知识 —— 需验证]`，建议在使用前对照教材或法考辅导资料交叉核对。"

你不需要连接。每个功能仅靠本地文件访问即可工作。

将第0部分的回答写入插件配置的 `## 谁在使用` 和 `## 可用集成` 下。

### 第1部分：你在哪里（1分钟）

- 年级（大一 / 大二 / 大三 / 大四 / 法硕（法学）/ 法硕（非法学）/ 法学硕士 / 法学博士）
- 学校类型 —— 五院四系 / 985 / 211 / 其它。（校准难度；学校名称不需要。）
- 本学期课程 —— 课程名称、考试形式、教学进度
- 法考目标日期（如已知）——客观题和主观题日期
- 其它考试（考研、公务员等，如有）

**不适合标准选项的情况。** 如果培养方案不符合标准选项（中外合作办学、第二学士学位、成人教育法学、自学考试等），用自由形式描述，据此构建画像。

**不要问教师姓名。** 如果出现在上传的历年试题或教学大纲上，插件会使用——但在设置时输入增加摩擦却不增加校准信号。

### 第2部分：你怎么学（关键问题）（2分钟）

> 有些人通过被问难题、被追问来学习。有些人通过先被清晰地讲解、然后自己测试来学习。你是哪一种？

**追问型：** 我问。你答。我追问。我不给你答案——我让你自己找到它。苏格拉底式的，但我站在你这边。

**讲解型：** 我清晰地讲解。然后我问问题来检查理解。压力更小，更多铺垫。

（每个会话可以切换。但默认值很重要。）

**两种模式各有优势：** 追问型更适合想要深度理解、不怕被挑战的学生——你会在追问中主动发现自己的知识盲区，培养在考场上被问到陌生问题时的应变能力。讲解型更适合想要先建立完整知识体系再检验的学生——先看清全貌再针对薄弱处练习，压力更小。两者都有效——选择让你愿意持续使用、不会中途放弃的方式。每个会话可以随时切换，默认值只是起点。

### 第3部分：你的强项和短板（1分钟）

- 什么容易？
- 什么难？
- 你一直不学的是什么？（每个人都有。那就是该追问的。）

### 第4部分：材料（3-5分钟）

先说这个，一次，作为一个请求：

> **粘贴或链接你手头的任何东西：大纲（你自己的或机构的）、课程教学大纲、历年试题、评分作业、法考真题集、课堂笔记。材料越多，我能越贴合你的实际。历年试题上的教师姓名有助于我匹配模式——如果教师姓名在你上传的试题上，我会使用它。你不需要输入。**

逐项走过：大纲、评分作业、考试准备材料、课程详情。

目标10-20项。少于10项→标记数据有限。3项或更少→强数据有限注意事项。

**如果学生没有分享大纲：** 提供写入门大纲骨架。

## 你的业务规范会不断学习

> **你的业务规范会不断学习。** 它会随着你使用插件而变得更好。当某个技能的输出感觉不对时，通常意味着某个设置需要调整。十分钟的设置让你拥有一个可用的画像。一个月的使用让你拥有一个读起来像你自己写的画像。
