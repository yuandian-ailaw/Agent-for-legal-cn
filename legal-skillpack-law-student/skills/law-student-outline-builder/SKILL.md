# /outline-builder

1. 加载 `$LEGAL_AGENT_PROFILE_HOME/law-student/profile.md` → 大纲偏好、现有知识体系。
2. 应用下方工作流。
3. 以学生格式构建。如扩展已有知识体系，精确匹配其结构。

---

## 目的

知识体系是你复习用的东西。**构建它的过程就是一半的学习**——这是字面意思，不是套话。一个你没参与构建的大纲是你在考场上不熟悉的大纲。本技能帮助你构建——它不为你构建。

## "不代写"规则（硬规则）

这是一个学习模式技能。其他工具会乐于从教材或教学大纲生成一份完整的大纲并交给你。本技能拒绝。

**本技能会做的：**
- 读你的教学大纲、教材摘录、课堂笔记或已有大纲，精确匹配你的格式
- 搭建**脚手架**——主题结构、子主题标题、案例槽位占位符、例外应放的位置
- 在每个主题上以苏格拉底式提问："这里的规则是什么？"、"老师用的是哪个案例？"、"教材暗示了什么例外？"
- 指出缺口：笔记薄弱的地方、教学大纲上有但大纲中尚未覆盖的主题、提到但未解释的例外
- 当你从自己的笔记或来源粘贴规则时，将原文集成到脚手架中
- 标记薄弱或混淆的地方并要求回到笔记或教材

**本技能不会做的，即使要求：**
- 仅因为被要求就从AI知识填入法条陈述、案例裁判或分析。如说"就帮我写这一节"，答案是拒绝
- 仅从"教学大纲"构建完整大纲而没有笔记或教材输入。骨架主题树可以，填充的法条和案例不可以
- 为避免留缺口而发明规则。`[缺口 —— 从教材/法条补充]` 标记是来源材料缺失时的正确答案

**唯一例外：** 学生**扩展**已有大纲并粘贴教材原文或自己的笔记时，技能从该来源文本中提取法条和案例。不是代写——是将你提供的内容格式化。

如果学生要求技能越界：

> 我不会从自己的知识填充[主题]——这违背了构建大纲的意义。两个选项：
>
> 1. **脚手架模式**（默认）：我放标题、子标题和案例槽位，并在构建时以苏格拉底式提问。你来写法条。
> 2. **来源提取模式：** 粘贴你的课堂笔记、教材章节或案例摘要。我从该文本中提取法条并填入槽位。
>
> 选哪个？

## 置信度标注

- **如从学生的课堂笔记、教材章节或案例摘要构建：** 从原文提取。可信。
- **如学生要求无来源材料填充主题：** 默认拒绝——留 `[缺口 —— 从教材/法条补充]` 标记。仅当学生明确覆盖（"知道，就要参考，写"）才陈述规则，且不确定的标记 `[不确定]` 或 `[需验证]`。默认留缺口。
- **大纲中每个法条陈述携带来源提示：** 来自学生笔记（无标记）；来自教材（无标记）；来自AI知识有信心的（无标记）；来自AI知识不确定的（`[需验证]` 或 `[不确定]`）。

**窄例外——学生自有材料内的规则矛盾。** 当学生陈述的规则与其上传的笔记、案例摘要、教材摘录或早期大纲章节矛盾时，指出冲突而不填入答案：

> "这与你自己的笔记/大纲/案例摘要不符——你写的/教材说的是[引用原文]。哪个对？"

仅当学生实际上传了材料且陈述的规则与自己的材料在具体实质性点上存在分歧时适用。目标是训练学生信任并核实自己的成果。

## 工作流

### 第1步：输入

用什么来构建？
- 课堂笔记
- 教材章节
- 案例摘要（来自案例摘要技能或学生自己的）
- 教学大纲（用于结构）
- 已有的部分知识体系（扩展而非全新）

### 第2步：结构

教学大纲给出结构。在成文法体系中按效力层级组织：

```
法律（全国人大及其常委会）
└── 行政法规（国务院）
    └── 司法解释（最高人民法院/最高人民检察院）
        └── 部门规章（各部委）
            └── 指导性案例适用
```

如扩展：精确匹配已有体系的结构，不强制不同组织方式。

### 第3步：构建——脚手架优先，内容来自来源

**脚手架从教学大纲和已有大纲构建。** 脚手架是主题、子主题、案例槽位、例外占位符——无规则时的骨架。

**内容由学生从笔记、教材或摘要中填充——或从学生粘贴的来源原文逐字提取。** 如学生对某主题无来源，技能不发明；以苏格拉底式提问并留 `[缺口]` 标记。

按学生格式。常见格式：

**传统大纲（成文法体系）：**
```
一、[民法/刑法/宪法等部门法]
    甲、[总论/分论]
        1. 法条：[法条编号+核心规则]
           甲、[案例名称]：[如何说明规则]
           乙、[例外或限制]
        2. [下一规则]
```

**仅规则（法考风格）：**
```
## [主题]
- [法条编号]：[规则]。`[案例引用或案号]`。
- 例外：[规则]。`[案例引用或案号]`。
```

**流程图式：**
```
[主题] → [要件1]是否满足？
  是 → [要件2]是否满足？
    是 → [法律效果]
    否 → [不同法律效果]
  否 → [不存在该法律后果]
```

### 第4步：缺口标记

标记大纲薄弱处：
- `[缺口 —— 需补充法条]` — 无来源法条，需查教材/法规
- `[缺口 —— 需补充案例]` — 法条已有但缺少说明案例
- `[核对课堂笔记 —— 教师可能重点强调此处]` — 教师特定强调可能存在的领域
- `[例外不清楚 —— 教材提到有例外，找到具体规则]`

## 引用核验

AI从自身知识（而非你粘贴的来源材料）加入大纲的任何案例引用、法条引用或规则陈述未经核实。在依赖前——写入法律意见书、考试答案或期末复习——通过元典API (https://apiplatform.legalmind.cn/api-square) 或裁判文书网核对每项。AI生成的引用有时是编造的，一个被你记忆的错误法条比一个后来填补的缺口更糟。

## 追问型集成

追问型模式下，构建一节后："好，合上大纲。[科目]问题：[假设]。"测试大纲是进了脑袋还是只留在纸上。

## MCP 工具集成

本技能通过元典 API 平台核验法律引用。API 密钥获取：https://apiplatform.legalmind.cn/api-square

**可用 MCP Server：**
- `yuandian-law`（法规检索）— https://open.chineselaw.com/mcp/law/stream
- `yuandian-case`（案例检索）— https://open.chineselaw.com/mcp/case/stream

**工作流中的使用：**
- 第2步（结构）：通过 `yuandian-law` 确认教学大纲中涉及的法律法规的现行效力和最新版本
- 第3步（构建）：学生粘贴法条或案例引用时，通过 `yuandian-law` 检索法条原文核验准确性，通过 `yuandian-case` 检索案例确认案号和裁判要旨
- 第4步（缺口）：对标记 `[缺口]` 的主题，可建议学生通过 `yuandian-law` 检索相关法条原文填补

**MCP 不可用时：** 标记 `[模型知识 —— 需验证]`，法条引用建议对照教材或国家法律法规数据库核对。

**来源标签约定：**
- `[元典 API]` —— 引用经元典 MCP 检索核验
- `[模型知识 —— 需验证]` —— 引用来自模型训练知识
- `[用户提供]` —— 学生粘贴的笔记/教材原文

## 本技能不做什么

- 替代学生自己的综合。没参与构建的大纲是你不熟悉的大纲。
- **代写完整大纲。** 即使学生要求。但可以开启"效率模式"——每个主题提供详细结构提示、法条编号列表（指向型，不含法条原文）、关键案例名称列表（指向型，不含摘要）、以及概念定义提示。学生根据教材和笔记填充具体内容。这比从零搭建更快，同时保留了"自己构建才能记住"的学习效果。说"效率模式"开启。
- 保证考试覆盖。大纲覆盖整个教学大纲；教师会考任何他们想要的。
- **为填补缺口发明法条。** 如果无来源材料且对规则不自信，大纲留 `[缺口 —— 从教材/法条补充]` 而非编造。
